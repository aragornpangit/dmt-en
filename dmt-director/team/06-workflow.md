## 4. Workflow

1. **anam researches**: anam **dispatches `ana-e` sub-agents directly (fill every slot for independent units)**, splits sub-questions and gathers evidence in parallel; anam verifies the primary sources and closes the work out into a research report, which **lands in** `docs/analyst/` **after director review**; **anam closes out the task, and that batch of `ana-e` sub-agents is reclaimed with the close-out**.
2. **The director summons `pde{n}` to produce the PRD, SPEC and tickets**: once the director has agreed with the user on the boundaries, the out-of-scope items and the acceptance criteria, it lists the product units and **dispatches `pde1…pde{n}` in parallel to draft them** (one unit per pde, every unit without dependencies dispatched at the same time and none left out); `pde{n}` **drafts** into `docs/pd/prd/`, `docs/pd/spec/` and `docs/dev/tickets/`, and the director accepts and finalizes them one by one: write the PRD and SPEC from the research report ([`/to-spec`](https://raw.githubusercontent.com/mattpocock/skills/main/skills/engineering/to-spec/SKILL.md), with acceptance criteria that are testable item by item), then use [`/to-tickets`](https://raw.githubusercontent.com/mattpocock/skills/main/skills/engineering/to-tickets/SKILL.md) to slice the SPEC into development tickets, landing them in `docs/pd/prd/`, `docs/pd/spec/` and `docs/dev/tickets/` respectively (file header `Status: pending review`), **self-reviewing against the document gate** (acceptance criteria testable item by item, `spec-seq` aligned, slices independently verifiable, Files not overlapping, dependencies acyclic; cross-examine with [`/grill-me`](https://raw.githubusercontent.com/mattpocock/skills/main/skills/productivity/grill-me/SKILL.md) and [`/grill-with-docs`](https://raw.githubusercontent.com/mattpocock/skills/main/skills/engineering/grill-with-docs/SKILL.md)); once it passes, change the status line in place to `Status: approved` and hand it to devm for scheduling.
3. **devm takes the tickets**: devm reads this batch's tickets in `docs/dev/tickets/` (drafted by `pde{n}`, finalized by the director, already through the document gate), checks the `spec-seq` alignment and that the criteria are complete, then schedules by dependency; **devm does not split tickets or change criteria** — missing items are reported to the director to fill in. devm is responsible for reviewing and integrating the department's deliverables.
4. **devm dispatches engineers directly (fill every slot for tickets without dependencies)**: devm **spawns `dev-e` sub-agents directly** (one worktree per ticket, every ticket without dependencies in parallel), handing the ticket (path, ticket base, Files boundary, acceptance criteria, `timeoutMs`, report format) to the engineer to implement; devm creates the worktree itself, collects the diff for an **implementation-level first check**, and verifies the primary sources. anam does the same with **`ana-e`** (split sub-questions, fill every slot for parallel evidence gathering, verify the primary sources).
5. **devm implementation-level acceptance**: check the diff and the evidence, build and test, and send anything unacceptable back to the original implementer; no merge in this step.
6. **Independent acceptance and release**: devm code gate → devm dispatches `reviewer{n}` for independent acceptance → devm merge / push. Gate and independence details: [`team/07-discipline.md`](07-discipline.md) §5.3.
7. **Parallelism**: fill every subagent slot for tasks without dependencies; serialize only real dependencies and state the reason. Dispatch templates: [`team/07b-dispatch.md`](07b-dispatch.md).

### 4.1 PRD template (`pde{n}` drafts, director finalizes)

`Problem Statement` / `Target users and scenarios` / `Solution overview` / `User stories (acceptable)` / `Acceptance criteria` / `Out of scope` / `Open questions`.

### 4.2 SPEC template (`pde{n}` drafts, director finalizes)

`Problem Statement` / `Solution` / `User Stories` / `Acceptance criteria (testable item by item)` / `Implementation decisions` / `Test seams` / `Out of Scope` / `Change history`.
The SPEC must be self-contained: every User Story must be convertible into a ticket and test cases.

### 4.3 Ticket template (`pde{n}` drafts, director finalizes)

`Goal` / `Input SPEC sections` / `Acceptance criteria (testable item by item)` / `Files scope` / `Build extras (**mandatory whenever the ticket touches gradle / clean build**: a new worktree needs `local.properties` (sdk.dir) plus symlinks for the two vendored directories under `app/src/main/jni/` (`opencv-mobile-4.13.0-android` / `ncnn-20260526-android-vulkan` → the same paths in the main repo) plus `ANDROID_HOME`; all gitignored, not deliverables)` / `Dependencies (ticket numbers)` / `timeoutMs` / `Status` / `Implementation status (appended by devm)`.
Tickets are sliced vertically along tracer bullets by `pde{n}` with [`/to-tickets`](https://raw.githubusercontent.com/mattpocock/skills/main/skills/engineering/to-tickets/SKILL.md) and finalized by the director; **numbering follows dependency order and `spec-seq` aligns strictly with the SPEC**; Files scope entries must not overlap, and Dependencies must be acyclic.
