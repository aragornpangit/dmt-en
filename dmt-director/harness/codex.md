## 1. Skill discovery directories

| Level | Directories |
|---|---|
| Project level | `.agents/skills/`, `.codex/skills/` |
| User level | `~/.agents/skills/`, `~/.codex/skills/` |

## 2. Startup and permissions

- `codex -a never` (`-a never` = no per-command approval). The auto-mode check recognizes `-a never` / `--ask-for-approval never` / `--yolo`.
- **Entering a project directory for the first time requires a manual trust confirmation (one-off)**: `-a never` does not exempt this step; when a pane is stuck at the trust prompt, the director confirms manually and then re-runs `setup-team.sh`.

## 3. Skill invocation line

- dmt role skills: `/dmt-<role>` (original name).
- **mattpocock plugin skills carry the qualified prefix `mattpocock-skills:<name>`** (generated by `lib-dmt.sh: dmt_skill_ref` from `harness_matrix.yaml: skill_prefix`).
- Compatibility copies and the plugin are **either/or**, to avoid registering same-named skills twice (the shim lives at repo root `scripts/sync-mattpocock-codex-compat.sh`).

## 4. How skills reach the model

- The launcher accepts a first-round prompt (matrix `first_prompt: true`) ⇒ **the role skill and the task are delivered in one shot at startup** (`dmt_start_has_first_prompt` check); do not count on "start first, then type a slash command".
- Subagents: `spawn_agent` dispatches, `wait_agent` collects results; for the dispatch template see "Codex harness hosting" in [`../team/07b-dispatch.md`](../team/07b-dispatch.md).
- When there is **no** `spawn_agent` interface inside the herdr role pane, do not fake a team by nesting `codex exec` from a shell; finish this role's work in this pane and record `[SUBAGENT_UNAVAILABLE]`.

## 5. Mandatory skills

`/<name>`; for mattpocock use `mattpocock-skills:<name>` (e.g. `mattpocock-skills:code-review`).

## 6. Two hard constraints (measured end-to-end across three roles on 2026-11-06; must be followed)

### 6.1 The sandbox must be `danger-full-access`, otherwise pane communication is completely broken

- The default sandbox of `codex -a never` is **Workspace** (restricted). Measured: inside codex's shell, connecting to herdr's unix socket fails outright with `Error: Os { code: 1, kind: PermissionDenied, message: "Operation not permitted" }` ⇒ **`send-msg.sh` doorbell inevitably skips** (`WARN: pane label 'director' not found`), `dmt_pane_by_label` returns all-empty, and identity self-check plus file-claim stop working.
- Check comparison (same script, same pane, only the sandbox changed):

  | sandbox | `herdr pane list` | doorbell |
  |---|---|---|
  | default `workspace-write` | ❌ PermissionDenied | ❌ WARN, only writes the file, no doorbell sent |
  | `--sandbox danger-full-access` | ✅ | ✅ director receives it and closes out on claim |

- ⇒ **dmt role panes must** use `codex -a never --sandbox danger-full-access` (the matrix `start_cmd` has been updated). Security implication: filesystem and network sandboxing are lifted; use only on controlled development machines / in containers (the same trust assumption as `--dangerously-bypass-approvals-and-sandbox`).

### 6.2 codex's shell reuses a **stale long-running shell environment** (`HERDR_*` points at an abandoned session)

- Measured: the codex process's own `/proc/<pid>/environ` has the **correct** `HERDR_WORKSPACE_ID=w9`, `HERDR_SESSION=bcr-nh`; but inside its `exec_command` (`bash -lc`) they are `w1` / `bcr-nihui` (a session that no longer exists) ⇒ even starting with `env HERDR_…=<correct value> … codex` **does not help** (it reuses the resident shell of the unified executor and does not read the parent process env).
- Symptom: `send-msg.sh` reports `server_not_running .../sessions/bcr-nihui/herdr.sock`; the anam side likewise reports herdr unavailable.
- **Already fixed on the dmt side (eighty-third time)**: `lib-dmt.sh` gains `dmt_herdr_env_fix [target label]` — when the current socket is unreachable, it scans `~/.config/herdr/sessions/*/herdr.sock`, takes the **unique** hit that "contains the target label and has `cwd==$PWD`", and exports the correction (on multiple hits it never touches anything, never guesses). `send-msg.sh` calls it before addressing.
  - Why a separate function: `pane="$(dmt_pane_by_label …)"` is a **subshell**, and exports inside the function do not propagate back to the parent process ⇒ otherwise you get "pane found, but sending still goes through the stale socket" (this step was actually observed).
- codex spawning its own subagents (`spawn_agent`) has a separate problem: measured, the **tool was invoked** (1/2/2 times for the three roles respectively) but **the task payload was not delivered** (the subagent replied "message queue is empty" / role drift) ⇒ record `[SUBAGENT_UNAVAILABLE]` for that round and let this pane act on its behalf.

## 7. Specific constraints

- Read the concurrency cap from `[agents] max_concurrent_threads_per_session` (matrix `max_subagents_config`); the matrix static default is 8.
- Session tree `tree_mode: herdr` (goes through the herdr session tree, not an in-process fork).
- `cbc-herdr` is **not** needed (herdr recognizes codex natively).
